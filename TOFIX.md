# TOFIX

Findings from a code scan on 2026-10-17.

## High

- `src/site.rs:946-974`, `src/templates.rs:269-302` - Content assets cannot be linked or embedded via `@/...` despite `src/markdown.rs:198-211` and unit test `images_and_links_both_resolve_content_paths` (`src/markdown.rs:534-567`) explicitly supporting `@/` on both links and images. `Site::resolve_content_path` and `Model::resolve` only consult `page_lookup` and `section_lookup`, never `site.assets`, so `![alt](@/blog/pic.png)` or `get_url(path="@/blog/pic.png")` always fails with `no content file matches "blog/pic.png"`. Register content assets in a lookup table (or fall back to `site.assets`) in both resolvers and track the asset in `link_sources` when needed.
- `src/site.rs:1062`, `src/templates.rs:114, 142, 197-200`, `src/render.rs:362-368, 390-398, 533` - `.tera` content pages and sections (`BodyKind::Tera`) have empty `content`, `word_count = 0`, and `summary = null` everywhere outside their own standalone page/section render. `Site::render_body` returns `Rendered::default()` for `BodyKind::Tera`, and `render_page` / `render_section` only populate a local `view["content"]` clone when rendering that individual output. As a result, dated `.tera` pages in Atom feeds (`render_feed` at `src/render.rs:533`), `.tera` pages in `section.pages` / `term.pages` listings, and `.tera` pages/sections fetched via `get_page()` or `get_section()` have an empty `content` field.
- `src/plan.rs:140-143, 173-177` - Manifest `sources` for `.tera` content pages and sections are incomplete in three ways:
    1. When a page or section uses `body_from` pointing to a `.tera` translation (`page.body_source` / `section.body_source`), `page.file.body` is empty and `page.file.body_kind` may not be `BodyKind::Tera`, so `plan.rs` checks the wrong file instead of the `body_source` file.
    2. `plan.rs` only runs `load_data_paths` on `.tera` content bodies and never checks `reads_other_pages(&body)`, so a `.tera` page calling `get_section(...)` or `get_page(...)` does not list `all_content` in its `sources`.
    3. `plan.rs` never extracts `template_references(&body)` (`{% include %}` / `{% import %}`) from `.tera` content bodies, so included template files are omitted from `sources`.
- `src/plan.rs:341-352`, `src/render.rs:614-643` - Manifest `sources` for `sitemap.xml` omit taxonomy translation files (`taxonomy.translations_file`, e.g. `i18n/tags.toml`) even though `render_sitemap` (`src/render.rs:615-628`) uses `term.translations` to emit `<xhtml:link rel="alternate">` entries for taxonomy terms. `Plan::compute` also discards the `cross` and `data` (`load_data_paths`) values returned by `site.template_sources("sitemap.xml")` and omits `common(&fallback)` (`i18n/<fallback>.toml` and theme config).
- `src/plan.rs:165-178, 207-223`, `src/render.rs:431-447` - Manifest `sources` for `YearArchive` and `Section` omit translated content files that affect rendered `translations` and `alternates`. `render_year_archive` checks whether each translated section in other languages has `other.front.year_archives` enabled and at least one page in `year` (`self.site.years_of(other)`), and reads `other.title()`, yet `archive_sources` (`src/plan.rs:211-215`) only includes `content_of_lang(&section.lang)`. Similarly, `Section` outputs include `section.translations` (which carries the `title` and `permalink` of paired `_index.<other_lang>.md` files), but `plan.rs:165-178` only includes `content_of_lang(&section.lang)` unless the template triggers `cross`.

## Medium

- `src/config.rs:489-490`, `src/plan.rs:182-189, 265-276, 363-376` - `url_prefix = "/"` is explicitly allowed by `Config::validate` (and tested in `src/config.rs:489`), but any site using `url_prefix = "/"` unconditionally fails in `Plan::compute` with output path collisions because the language's root section (`index.html`) and 404 page (`404.html`) collide with `Kind::Root` (`index.html`) and the global fallback `Kind::NotFound` (`404.html`). Either reject `url_prefix = "/"` during config validation or skip emitting separate root redirect / global 404 outputs when a language already occupies `/`.
- `src/content.rs:129`, `src/site.rs:411, 634-646` - `SectionFront` declares `pub translation_key: Option<String>`, so `translation_key = "..."` is accepted in `_index.<lang>.md` front matter without error, but `build_sections` (`src/site.rs:411`) hardcodes `key: file.components.join("/")` and ignores `front.translation_key`. Either honor `front.translation_key` (and guard against duplicate same-language section keys in `pair_translations` at `src/site.rs:634-641`, which currently overwrites silently with `.insert()`) or remove `translation_key` from `SectionFront` so serde rejects it as an unknown field.
- `src/content.rs:116-119`, `src/plan.rs:224, 252`, `src/site.rs:1128-1135` - `SectionFront::generate_feeds` is documented as `"Defaults to the language's generate_feeds for the root section and to false for any other section"`, but for the root section it is completely ignored: `plan.rs:224` skips root sections (`if site.section_feeds(section) && !section.is_root()`) and `Site::language_feeds` (`src/site.rs:1133`) only checks `config.language(lang).generate_feeds`. Setting `generate_feeds = true` or `generate_feeds = false` in a root `_index.<lang>.md` has no effect.
- `src/site.rs:397-425, 492-497, 534, 599-608` - Draft section handling is inconsistent across sections, pages, and assets:
    1. `section_is_drafted` (`src/site.rs:599-608`) checks `dir.join(format!("_index.{}.md", file.lang)).is_file()` on disk instead of consulting `self.drafted_sections`. This fails when the drafted section index is unsuffixed in a single-language site (`_index.md`) or uses `.html` / `.tera` (`_index.en.html`, `_index.en.tera`).
    2. `under_drafted_section` (`src/site.rs:492-497`) drops assets under any ancestor in `drafted_sections`, whereas `build_sections` and `build_pages` only check the immediate directory's index. If a parent section has `draft = true` and a nested subsection has `draft = false`, the subsection and its pages are built while its co-located assets are dropped.
- `src/site.rs:679-703`, `docs/src/content.md:82` - `resolve_body_sources` verifies `if !self.pages[i].file.body.trim().is_empty()` for pages (`src/site.rs:674`) and errors when both a body and `body_from` are present, but omits that check for sections (`src/site.rs:679-703`), silently discarding the section's body contrary to `docs/src/content.md:82`. In addition, if a root section sets `body_from` to a language whose root section is implicit (`self.sections[source].file.is_none()`), `resolve_body_sources` accepts it and `render_bodies` silently leaves the body empty.
- `src/site.rs:389-425, 513-518, 634-641` - Duplicate section index files in the same directory and language (e.g. `_index.en.md` and `_index.en.html`, or `_index.md` and `_index.en.md` in a single-language site) are not rejected. `build_sections` pushes both into `self.sections`, and `section_lookup`, `section_index`, and `section_groups` silently overwrite the first entry with the second, leaving the first section orphaned with no pages. Also, `let mut dirs: BTreeSet<Vec<String>>` in `build_sections` (`src/site.rs:389-393`) is dead code that is populated and never read.
- `src/site.rs:204-210`, `src/templates.rs:277-282` - `strip_lang` uses `rel.rfind(&format!(".{lang}."))` across the entire relative path string. In a single-language site where a content file omits the language suffix (e.g. `content/dir.en.name/post.md` or `content/blog/v1.en.2.md`), `rfind(".en.")` matches inside the directory name or file stem and corrupts the lookup key to `dir.name/post.md` or `blog/v1.2.md`. It should only strip `.{lang}` when it immediately precedes the final file extension.

## Low

- `src/config.rs:314-326`, `src/content.rs:115, 313`, `src/plan.rs:81`, `src/site.rs:938, 1001` - `Config::validate` checks `..` and strips trailing `/` on `[[publish]]` entries (`src/config.rs:335-351`), but does not normalize or validate `output_dir`, `content_dir`, `templates_dir`, `static_dir`, `sass_dir`, `i18n_dir`, `themes_dir`, `feeds.filename`, `taxonomy.paginate_path`, `taxonomy.translations`, or `SectionFront::paginate_path`. A trailing slash on `output_dir = "_site/"` or `content_dir = "content/"` produces double slashes (`"_site//..."` in manifest output paths at `src/plan.rs:81` and `"content//..."` in `link_sources` at `src/site.rs:1001`).
- `src/site.rs:160-177`, `src/templates.rs:427-431` - Template static analysis and `get_url` edge cases:
    1. `load_data_paths` (`src/site.rs:160-166`) uses `r#"load_data\(\s*path\s*=\s*"([^"]+)""#`, which misses calls where `format` or `required` precedes `path` (e.g. `load_data(required=false, path="...")`).
    2. When `load_data(path="data/missing.toml", required=false)` references a file that does not exist on disk, `load_data_paths` still adds `"data/missing.toml"` to the manifest's `sources`, causing incremental build tools to fail looking for a non-existent input file.
    3. `reads_other_pages` (`src/site.rs:170-177`) does not match `get_url(path="@/...")`, so a template using `get_url(path="@/...")` without other cross-page expressions does not record the target content file in `sources`.
    4. `get_url` (`src/templates.rs:427-431`) does not split `#fragment` suffixes on `@/...` paths, unlike markdown link resolution in `src/markdown.rs:262`.
- `src/templates.rs:596-600`, `src/markdown.rs:122-124` - The `markdown` Tera filter (`src/templates.rs:596-600`) hardcodes `smart_punctuation: false`, `highlight: false`, and `anchor_mode: SlugMode::Safe` instead of using the site's `[markdown]` and `[slugify]` settings. Additionally, `markdown.rs:123` extracts the code fence language with `info.split([' ', ',']).next()`, which yields `""` when there is a leading space after the backticks (e.g. ```` ``` rust ````) or a tab; `info.trim().split([' ', '\t', ',']).next()` should be used.
- `src/content.rs:242-251` - `split_front_matter` uses `rest.strip_prefix("\r\n").or_else(|| rest.strip_prefix('\n')).unwrap_or(rest)` after stripping `+++`, which allows a file starting with `+++anything` on the first line to be parsed as front matter instead of requiring the opening `+++` delimiter to be on its own line (as is required for the closing `+++` at `src/content.rs:255`).
- `src/serve.rs:16-39, 66-85` - `rssite serve` loads `Config` and computes `output_dir` and `watched_dirs` only once at startup (`src/serve.rs:16-27`). Editing `rssite.toml` while `serve` is running triggers `build`, but changes to `output_dir`, `theme`, or `[[publish]]` are not reflected in the HTTP server root or file watcher, and external files read via `load_data` (such as `data/*.toml`) are not watched.
- `docs/src/templates.md:7-19, 45, 69`, `docs/src/manifest.md:30-31`, `docs/src/getting-started.md:28`, `README.md:93, 163-180, 199` - Documentation discrepancies:

    2. `docs/src/templates.md:7-19` omits `archive.html` / `archive_template` (for year archive pages) from the template table and required-templates note, and `docs/src/templates.md:45` omits `description` and `extra` from the top-level `section` object passed to page and archive templates (`src/render.rs:660-669`).
    3. `docs/src/manifest.md:30-31` says section and taxonomy pages depend only on content files of their language (whereas default templates access `.pages`/`subsections`, causing `reads_other_pages` to include `all_content` of all languages at `src/plan.rs:121-123`) and omits `templates/sitemap.xml` and taxonomy translation files from sitemap dependencies.
    4. `docs/src/getting-started.md:28` lists `static/` as `(empty after init)`, but `rssite init` (`src/init.rs`) does not create a `static/` directory.
    5. `README.md:93` claims `rssite` caches its plan keyed on `hash(config) + hash(source tree)` (not implemented), `README.md:163-167` uses outdated `rsconstruct.toml` syntax compared to `docs/src/manifest.md:40-45`, and `README.md:173-180, 199` still contain pre-implementation "Open design questions" and roadmap text.
